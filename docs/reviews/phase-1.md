Found while fixing:

- **The session running the phase ran out of API credits** during round 1, while it waited on Fable. Fable's lead reviewer had already ended without writing up its own part, so the wait would never have finished. A new session took over, kept the four reports, and reviewed that part again.
- **Paper's panel radius drops to `radius-panel-sm` under 700px,** as the README says, so the radius spec expects that token at the test's phone width.
- **Card's flush well has a phone rule of its own,** so a planted defect in the desktop rule didn't reach the 414px test page.

### Rejected

- **#15, `clip-path` and transparent text** (overturned in round 2, #4). The common hidden-text patterns are caught: a 1px box with `overflow: hidden` fails the clip check, and `left: -9999px` fails the new start check. A panel hidden only by `clip-path` or `color: transparent` would still differ in the parity captures.
- **Closed panes' chips aren't checked hidden at 1280px** (Fable, low). The Accordion preview's PaneAccordion shows closed panes at rest, and parity compares it pixel by pixel. A chip left showing there costs far more than the 16px budget.
- **`--self` ignores the unmutated reference's own problems in its exit code** (Fable, low). The reference fails the wiring check by its documented defect. A planted defect counts only when it adds a problem the unmutated run lacks, so a broken check still fails the self-test.
- **`referenceDefectTest` accepts any failure on the reference** (Fable, low). Each listed test has a row that names its defect, and the package run must pass it.
- **The other class-only checks** (Fable, low): Paper's elevation, Table's size and padding, List's dense and inset, Chip's plate, small size and tones, Typography's colours and Avatar's variant. Each is in its preview, which parity compares at 1280px.
- **Specs that pin the reference's behaviour where the docs are silent** (Fable, low): LightField's default placement, Button's `type="button"` and useMediaQuery's first value. Where the docs are silent the reference is the spec (`docs/porting.md`), and each spec says so.
- **Keyboard halves that can't fail on a natively disabled List row or Card action area** (Fable, low). A control the keyboard can't reach can't be pressed, which is what the specs require. A port that kept it focusable and let the keys through would fail them.
- **`css-baseline`'s `once - before <= 1` accepts 0** (Fable, low). The lines around it require the sheet.
- **Typography's fluid spec tells the sizes apart only below 1429px** (Fable, low). The test viewport is fixed.
- **Flake risks in TimingChart's minimum bar and Stack's Tab from the body** (Fable, low). Not seen in this round's runs. They'd fail rather than pass.
- **TimingChart with `axisMax: 0`, and duplicate tick values or row names** (Fable, low). The reference does the same, and no doc covers a zero axis.
- **Chip's, ToggleButton's and Icon's stories hold args their renders ignore** (Fable, low). The args satisfy the required props for the story types, and no gate reads controls.
- **Table's story sorts ties oldest first when descending, and Chip's story drops focus after the last chip goes** (Fable, low). Both copy their preview's script exactly.
- **Avatar's stories lack the Example** (Fable, low). It uses Tooltip, so it joins in phase 2, as the runbook notes.

Found while fixing:

- **Round 1's hover spec could read a fade.** When the row rendered under the pointer, left there by the test before, its resting colour was read halfway through the fade-out. The spec now waits for the cell's transitions to end. Lighting the row first fails the old spec and passes the new one three times out of three.
- **The first alpha parser read `rgb(0, 0, 0)`'s last channel as an alpha,** so black text counted as transparent. The new unit test caught it, and the gates ran again with the fix.

### Rejected

- **#5, a TabPanel inside another component.** React writes a tab's HTML before it reaches the component that holds the panel, so no render can know of that panel in time. Panels among Tabs' children, and the elements in them, are wired in the server HTML. A panel inside another component is named after hydration, as in the reference, and `docs/reference-defects.md` now says so.
