## Scope

Modules (folders in `design-system/components/`): TextField, Select, Autocomplete, Checkbox, RadioGroup, Switch, Slider, Rating, TransferList, Fab and SpeedDial. Each has a section in the reference bundle, so each gets `<Name>.css` and its import in `src/styles/index.css`, in the bundle's order (the build checks it).

Some modules build on others, so port those first: TextField's field shell (`FieldBaseProps`, the label, helper and error wiring, `InputAdornment`) serves Select and Autocomplete; Fab serves SpeedDial. The reference shares `design-system/shared/_inputs-b-field.tsx` and `_inputs-b-list.ts` between the fields and TransferList: port what the plan's Base UI mapping doesn't cover into `src/internal/`, once.

The Base UI mapping for this phase (`docs/package-plan.md`): TextField and InputAdornment on Field and Input; Select and Option on Select (`native` stays a `<select>`); Autocomplete on Combobox and Autocomplete; Slider on Slider; Checkbox, Radio and Switch on the form-control adapter; Rating on RadioGroup, through the form-control adapter's wrapped change events (deviation 2); TransferList on CheckboxGroup, which supplies at most the selection's value state: Base UI's CheckboxGroup has `role="checkbox"` controls and none of the listbox the specs require (two multi-select listboxes, one tab stop each, typeahead, Shift+arrows, Ctrl+A), so the listbox is a port of `_inputs-b-list.ts`, and if the group doesn't fit either, say so in your report as the deviation from the mapping. Fab on Button, as the Button port is (`src/components/Button/Button.tsx`: Base UI's Button for the `<button>`, a plain anchor with `href`). SpeedDial is a plain React port, on Fab and Zoom. A deviation from the mapping needs its reason in your report.

## Rules that matter most

- `docs/porting.md`'s rules, all of them. Base UI where the plan maps a module to it; a faithful port of `reference.tsx` everywhere else, including the parts of a Base UI-backed module that Base UI doesn't cover: Select's chips, Autocomplete's match highlight (its groups and chips are Base UI's own parts, `Combobox.Group`, `Combobox.GroupLabel`, `Combobox.Chips` and `Combobox.Chip`), Rating's hover preview, half stars and the clear on a press of the current star (which Base UI's RadioGroup never reports: the spec wants `onChange(event, null)`), TransferList's move buttons and status.
- **Server HTML is usable before hydration.** Select's Default opens its list in place at load (`defaultOpen` with `PopoverProps` set to `disablePortal`, `disableScrollLock` and `disableEnforceFocus`), and the reference's server HTML holds that list, hidden behind its `<Fade in>` defect; the gate requires the package to show it (`tests/README.md`, "Server HTML": what the reference held, even hidden, the package must show). Base UI's portal renders nothing on the server (deviation 10), and the in-place host `src/internal/popup-layer.tsx` gives is a `display: contents` span Base UI's portal fills in a layout effect, so an open Select in place needs its own server path, as `ModalLayer` has for an in-place modal (`src/internal/modal.tsx`): the layer for the client, and an in-place render that hydration adopts for the server. The bar the gate sets (`visibleTexts` in `scripts/lib/capture.ts`): a text counts as shown when its box isn't empty and no ancestor hides it through `display`, `visibility`, an opacity of 0, a cutting `clip-path` or a transparent colour; where it sits isn't checked, so the server list needs a real box with its transition started entered, nothing more. SpeedDial's open dials at load (the Default and the four Variants) must show their actions in the server HTML, and the Default's label pills too (it sets `tooltipOpen`; the Variants' pills show only on hover and focus, which `tests/behaviour/speed-dial.test.tsx` pins). Zoom through `src/internal/transition.ts` renders `in` content visible on the server (deviation 9), but the reference's stagger (`useStaggered`, `SpeedDial/reference.tsx`, line 32) starts every delayed action at `shown = false`, so a faithful port would hand Zoom `in={false}` on the server and hide them. An open dial's actions must start shown when they render on the server or hydrate, and stagger only on client-side opens and closes, with the timing the specs require (`speed-dial.test.tsx`, the motion tests). Autocomplete's lists are absent from the reference's server HTML too, so they may be absent from the package's. Everything else in this phase is static markup.
- **The form controls** run on `src/internal/form-control.tsx`. Keep its tests green and unchanged. Add contract tests on the components, in `src/components/<Name>/<Name>.test.tsx` (the `browser` project), that pin deviations 1 to 6 on Checkbox, Radio and Switch as `docs/package-plan.md` asks: the ref's element, event targets, attribute forwarding, focus and blur, and that validation and `FormData` still work. Deviation 6 (a Radio outside a RadioGroup) is the gap to watch: a lone Radio is a one-radio group, and its `checked`, `defaultChecked`, `onChange(event, true)` and form value must work.
- **Events.** Where the documented callback takes a React event and one exists, pass it (TextField's `onChange` gets the input's ChangeEvent). Where Base UI reports a change with no React event behind it, use the adapters in `src/internal/events.ts` and the ChangeEvent-shaped wrapper of `form-control.tsx`. The behaviour specs say what each callback must receive; read them before you choose.
- **Placement.** Select's list and Autocomplete's popup sit on the shared popover material (`gl-popover`). To land on the reference's pixels, place through `src/internal/anchor.ts` (`toPositionerProps`, `toWholePixelOffsets`) as Popover and Menu do; every `PopoverProps` flag (the type is `Partial<PopoverProps>`: `disablePortal`, `disableScrollLock`, `disableEnforceFocus`, `container` and the rest) goes to the layer `src/internal/popup-layer.tsx` gives.
- **Type.** The system's typeface is Satoshi, named first in `--font-sans`. Use the tokens and the `text-*` classes; add no font files and no `@font-face` to `src/`. The gates, Storybook and the specs load it from `fonts/`, which `npm run fonts` fills (done in your worktree).
- **Stories.** Every Default renders its preview's "Default" section and follows `stories/README.md`'s Controls rules. Read `tests/storybook/interactions.ts` before writing a Default: the Storybook gate replays those steps and looks for the roles and names they name. One behaviour only that gate checks: Autocomplete's second step presses the closed input to reopen the list, as the reference does on a left mousedown (Base UI's Combobox has it as `openOnInputClick`, on by default). A stateful Default lists its controlled prop through `LiveArg` with the preview's default as its arg, and logs its callbacks: Checkbox's and Switch's `checked` (true), RadioGroup's `value` ("node"), Rating's `value` (4), Select's and Autocomplete's `open` (true, the list open in place as the preview opens it) and SpeedDial's `open` (true); `onClose`, a choice and the other dismissals set `open` back to false. Select's and Autocomplete's Defaults may list `value` and `inputValue` as well. TextField's and Slider's Defaults list `value` through `LiveArg` too. TextField, Slider and Rating have no interaction entry (the comment in `interactions.ts` says why), so the Controls check alone proves their `value`. TransferList's `value` is an object, so its Default lists its other props (the titles, `showMoveAll`, `listHeight`, `disabled`). Fab's lists `variant`, `size`, `extended`, `disabled` and its `aria-label` as a text control. If an arg changes nothing in the server HTML, list it under `afterHydration` in `tests/unit/stories.json` with that reason. TransferList's stories file needs a phone twin (`tests/ssr/layout.json`).

## How to check your work

- `npx vitest run --project behaviour:package tests/behaviour/<name>.test.tsx` (the same spec on the reference: `--project behaviour:reference`, after `npm run reference`).
- `npm run reference && node scripts/parity/run.ts --only components/<Name>`: the report is in `reports/parity/index.html`, with reference, candidate and diff images per preview and state.
- `npm run build && npm run reference && node scripts/ssr/run.ts --only components/<Name>`.
- `npm run check:api`, then read the lines for your modules.
- `node scripts/ssr/layout.ts` (the stories in `tests/ssr/layout.json`). It refuses to run while a listed file is missing, naming every one, so it runs once TransferList's stories file exists; until then `npx vitest run --project unit tests/unit/stories.test.ts` checks the twin.
- `npx vitest run --project storybook` renders every story and fails on any axe violation.
- `npm run build-storybook && node scripts/storybook/run.ts --only <story ids>` drives the built Storybook for those stories and their docs pages. Story ids are the title's group and name, lower case: `inputs-select--default`, `navigation-speeddial--default`.
- Run the gates one at a time: they time out on harness steps when they share the machine.
